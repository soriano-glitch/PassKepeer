# ADR-001 — PassKeeper Phase 1 architecture (Proposed, pending PoC)

## Context

Offline-only personal password manager, iOS + Android, one TypeScript codebase, no backend, no account.

## Decisions

1. React Native + Expo development builds + strict TypeScript. Native security modules need a dev build.
2. Expo Router for file-based navigation.
3. Application-layer encryption of sensitive fields and an encrypted SQLite file (defense in depth).
4. Key hierarchy: Master password -> Argon2id(random salt) -> KEK -> wraps random 256-bit VDK.
5. Biometric unlock releases a device-bound wrapped copy of the VDK. Biometrics never replace cryptography.
6. Backups use a separate file, own salt, own Argon2id key from a recovery password, AEAD, versioned header.
7. No cloud sync in v1; keep a sync-ready boundary (stable IDs, timestamps, VDK never leaves device).

## Key hierarchy

Master password -> Argon2id(salt_m) -> KEK -> unwrap -> VDK -> HKDF("db"/"fields").

## Consequences

Native-module integration is the main schedule risk. VDK exposure in JS memory while unlocked is residual
risk. Compromised or rooted devices are out of scope and require documentation.
